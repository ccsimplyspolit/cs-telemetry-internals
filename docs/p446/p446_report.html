Deep audit — 21 agents, 5 aspects, 3 skeptics each

The audit workflow spawned 5 aspect-analyzer agents (coverage / spoofing / stealth / update-resistance / server-validation), then 3 adversarial skeptics per aspect trying to refute each claim, then a lead auditor synthesizing everything. 1.76M subagent tokens over 14 minutes. Below are all findings the synthesis surfaced, and how each is resolved in v5.

P0 Restart-loop persistence via update_target.txt

Function: sub_100859E0 @ RVA 0x000859E0, tick-driven by sub_10085F00.

Mechanism: reads csgo_gc/update_target.txt each frame, latches sticky byte_106F7E25 = 1 when a newer version marker appears, then issues engine _restart once the server drains. A stale or planted file produces an indefinite reboot loop.

Fixed: sub_100859E0 added to g_patches[] as RET0_R; short-circuits at entry before any file read.

P1 18 identical {31 C0 C3} detector prologues

Whole-module SHA/MD5 of csgo_gc.dll trivially detects 18 identical 3-byte runs. Server-side hash comparison is the realistic threat model — Project446 backend cross-checks msg-9205 replies against expected native findings and has every incentive to hash its own DLL.

Fixed: 4-variant rotation over {31 C0 C3}, {33 C0 C3}, {29 C0 C3}, {B0 00 C3} at apply time. All return 0 in EAX. Per-build random seed picks the starting index and each subsequent patch advances the rotation. No two consecutive detectors share bytes.

P1 stdcall/fastcall stack-cleanup risk in bare RET stubs

Callee-cleans convention (ret imm) at some detector entrypoints (spotted via and esp, 0FFFFFFF8h prologue). A bare {31 C0 C3} leaves stack args on caller's stack.

Verified: all patched detector RVAs are cdecl or thiscall (ECX-in-register only). No caller-cleaned stdcall entry among the 18 detectors. The 4-variant rotation preserves this because every variant is a bare ret. If a future detector calling convention differs, add a {C2 XX 00} ret-imm variant explicitly.

P2 HwidBuilder second-caller channel

sub_100567A0 (MasterScan) calls sub_101D3C30 (HwidBuilder) at 0x10056C21 and feeds the assembled HWID string to sub_1004D400 (AddFinding) at 0x10056C33. Currently benign because AddFinding is RET, but the "spoof at HwidBuilder is a single choke-point" mental model was wrong.

Fixed: sub_101D3430 (MachineGuid reader) added as inline empty-MsvcString return via the SMBIOS pattern. Second exfil channel closed at leaf level — even if AddFinding were ever un-neutralized.

P2 Server-side msg 9205 fingerprints

sub_1006F850 hardcodes result_code = 3. Zero unsolicited 9205 flushes (both MonitorLoop and NativeModFlush are RET). Infinite clean streak on challenge-solicited 9205 differs from a real client that statistically emits benign findings.

Partial: Challenge9205 kept executable, replies remain valid empty. Full fix (inject 1-2 plausible low-severity findings into the outgoing proto) requires runtime hook and is documented as a P2 next step. Server-only detection surface — no in-DLL patch can fully close it.

P2 Steam handle collision + surface leak

Previous patcher set the same fakeSteam value at both call sites — two patched clients from the same build collided. Also SteamAPI_Init, SteamAPI_RegisterCallback, SteamAPI_RunCallbacks IATs were not stubbed; genuine steamID64 continues to arrive via Steam callbacks.

Fixed collision: each call-site gets its own fresh random handle. Callback surface documented as P2 next step (requires broader IAT rewrite of the callback registrar).

P3 Hardcoded GenuineIntel-000906EA + 0.0.0.0 sentinels

Every patched client emits the same Skylake i7-6700K CPUID signature and the literal 0.0.0.0 from GetPublicIP. Trivial clustering on backend.

Fixed: CPU signature picked from 11 real consumer parts (Intel Coffee Lake/Comet Lake/Alder Lake/Skylake + AMD Zen 2/3/4). GetPublicIP inline patch now emits a random non-RFC1918 IPv4 built at patch time (guardrails skip 10.x, 127.x, 172.16-31.x, 192.168.x).

P3 WinTrust / CryptCAT dead-code wrappers

sub_100515B0 (WinVerifyTrust), sub_10051690 (CryptCATAdminCalcHashFromFileHandle), sub_10051800 (dispatcher). Currently unreachable; both callers (Det:RogueThread, Det:DirModScan) patched. Dispatcher uses || short-circuit, not && — so just one needs to succeed.

Fixed: all 3 wrappers preemptively stubbed with {B0 01 C3} ("return TRUE"). Belt-and-braces cost = 9 bytes; blocks any future caller that a new build might introduce.

P3 No post-patch verification pass

Every "CONFIRMED" verdict in earlier analyses read patcher source, not the patched artifact. If a write failed silently the patcher didn't notice.

Fixed: Phase 8 re-opens the written file, walks the patch table, accepts any of 4 variants at RET0_R entries, checks the JMP at HwidBuilder, checks inline patches at SMBIOS/MachineGuid/GetPublicIP. Emits VERIFY N passed, M failed, K skipped. Fail-loud on mismatch.

Persistent HWID

The HWID is written to p446_hwid.txt next to the DLL on first patch, loaded on subsequent runs. This gives one stable identity across re-patches, DLL updates, and the guard's auto-repair loop — the server sees one player, not a rotating carousel.
