Attack chain that already works today. Any attacker with a browser can ① pull /api/pay/recent for a fresh list of paying users with SteamID64 + amount, ② hit http://213.152.43.203:3000/ to bypass Cloudflare + DDoS-Guard + rate-limit, ③ read /api/inventory/<steamId> for any of those users without auth, ④ pull /api/update/manifest to fingerprint the exact client build. No credentials required, no user interaction, no privileged network position.

P0 · Critical

11 findings · fix before launch
P0.1

PostgreSQL 5432 open to the internet

Proof
python -c "import socket,struct; s=socket.socket();
s.connect(('213.152.43.203',5432));
s.send(struct.pack('!II', 8, 80877103));
print(s.recv(1))"          # → b'S' (SSL supported)
Impact
Even with strong pg_hba.conf, this is a brute-force + CVE window. Mail, app, and DB all live on one host — a single Postgres misconfig is catastrophic.
Fix
listen_addresses = '127.0.0.1' in postgresql.conf. Any remote replication path must go through WireGuard/IPsec, not the public IP.
P0.2

MySQL 3306 open to the internet

Proof
Direct mysql -h 213.152.43.203 banner grab from the public internet. Bind is 0.0.0.0.
Fix
bind-address = 127.0.0.1 in my.cnf, or stop the daemon entirely if MySQL isn't in active use.
P0.3

Next.js origin :3000 bypasses WAF, DDoS-Guard, and Cloudflare

Proof
curl -sI http://213.152.43.203:3000/api/admin/beta
Returns the same 401 body as going through Cloudflare — with no rate limit, no JS challenge, no TLS, no DDoS filter.
Impact
Every downstream mitigation (CF rules, DDoS-Guard, HSTS enforcement, rate-limit) is defeated by hitting the origin IP directly.
Fix
Firewall :3000 to accept only from the reverse-proxy egress IPs (Cloudflare + DDoS-Guard IP ranges), drop everything else.
P0.4

Setup.exe is not Authenticode-signed

Proof
Get-AuthenticodeSignature Project446-Setup.exe → Status: NotSigned.
Impact
Anyone MITM-ing the download or the user's browsing session can swap the installer for a payload without triggering the usual Windows signature warning. SmartScreen shows "unknown publisher", which users routinely dismiss.
Fix
Buy a code-signing certificate (Sectigo, DigiCert). Sign with SHA-256 + timestamp countersignature. Add an ambient publisher-key check inside the installer as defense-in-depth.
P0.5

/api/pay/recent exposes donor PII without auth

New this checkpoint
Proof
GET /api/pay/recent → 200
{"donations":[
  {"name":"iliodor21","steamId64":"76561199831924243",
   "amount":350,"method":"yoomoney",
   "created_at":"2026-07-22T12:13:07.135Z", ...},
  {"name":"MR [Slendy]","steamId64":"76561198161461584",
   "amount":500, ...}
]}
Impact
SteamID64 is linkable to real identity via Steam's public profile. The list gives display name, avatar, exact sum, timestamp, method. Anyone can build a donor-profile database from this endpoint alone.
Fix
Public endpoint should return an aggregate — { total_donors_7d, total_amount } — not individual rows. If a "recent supporters" strip is needed, display name only, no SteamID, no amount.
P0.6

Internal URL leak — payment errors redirect to 0.0.0.0:3000

New this checkpoint
Proof
Every failed POST /api/pay/{create,topup,donate,callback} returns Location: https://0.0.0.0:3000/pay/failed?reason=<value>.
Impact
Confirms P0.3 (backend binds to 0.0.0.0, not loopback). The reason= parameter is user-influenced and may be an open-redirect primitive if downstream code reflects it into the client redirect target.
Fix
Always use a relative Location. Never emit 0.0.0.0 or absolute URLs. Allowlist the reason= values instead of reflecting free text.
P0.7

/api/inventory/<steamId> — cross-tenant IDOR without auth

New this checkpoint
Proof
curl https://project446.su/api/inventory/76561199831924243
Returns the target user's inventory. No cookie, no bearer, no owner check.
Impact
Scraping surface for every player's skins/items — including anything paid. Route also accepts any input (abcdefghij, {{7*7}}, ..%2Fadmin%2Fbeta) and echoes it as steam_id, which suggests input validation is missing altogether.
Fix
Regex-validate steamId against ^7656119[0-9]{10}$ at the handler boundary. Require auth; only owner or admin with inventory.read.other should be able to read someone else's inventory.
P0.8

SERVER_TOKEN stored plaintext, legacy shared mode still supported

New this checkpoint
Proof
Strings recovered from csgo_gc.dll: 
GC_FLEET_SERVER_ID=<uuid-from-admin-api>
SERVER_TOKEN=<plain-token-from-admin-api>
Legacy shared SERVER_TOKEN auth failed (no DATABASE_URL fleet mode).
using /gc/server/{long} + shared SERVER_TOKEN
Wrong SERVER_TOKEN, wrong GC_FLEET_SERVER_ID, ban, or nginx stripped Authorization.
Impact
Tokens live in plaintext csgo_gc.env on every SRCDS host. Legacy mode uses one shared token across the whole fleet — compromise of any single SRCDS = full fleet compromise. The nginx-Authorization note strongly implies the auth check is delegated to nginx rather than being backend-enforced, which composes badly with P0.3.
Fix
Retire legacy shared mode entirely (require DATABASE_URL). Rotate SERVER_TOKEN per SRCDS; hash in DB, never store raw. Ship tokens through a secrets manager, not a text file. The backend must enforce Authorization independently of nginx — no header, hard 401.
P0.9

Build-artifact path leaks developer workspace

New this checkpoint
Proof
csgo_gc.dll contains the compile-time path D:\!csgo\csgo_gc\build_ninja_win32\_deps\boost-src\....
Impact
Confirms the fork lineage (csgo_gc = mikkokko upstream), gives an attacker plausible internal-path strings for phishing, and exposes the build system (Ninja, Win32, boost via _deps/).
Fix
Pass /PDBALTPATH:%_PDB% to the MSVC linker on release builds; strip embedded PDB paths from the final DLL.
P0.10

WSS client can silently continue without cert verification

New this checkpoint
Proof
csgo_gc.dll logs: 
[WS] WARNING: CertOpenSystemStore failed, SSL verify may fail
The warning is emitted and connection proceeds. Fail-open, not fail-closed.
Impact
A local attacker who can plant a certificate in the user cert store (which requires no elevation) can full-MITM the WSS traffic to gc.project446.su: read GC messages, inject arbitrary messages, replay item transactions, harvest session material.
Fix
Fail-closed on CertOpenSystemStore failure. Better: pin the gc.project446.su TLS certificate hash inside the DLL and refuse anything else. Removes user-installed CA as an attack path.
P0.11

Update manifest is public — leaks version, hash, signature

New this checkpoint
Proof
GET https://gc.project446.su/api/update/manifest?platform=win32 → 200
version=0.7.6.8
format=gcup
file=update.gcup
size=31536194
sha256=d46b75f678b10b74900142efb1142a2236466b752c568b926eee8a649026b632
sig=a6Xib9psdBjq82Y4T2wSAkIBGUv7Oyrl0F46zGgTrobQ0vpwr7WyFhMihQOn2Si+krdjymKT+EyvZe3FTTqqDw==
url=/api/update/download?platform=win32
Impact
Not a direct RCE — the Ed25519 signature protects against payload swap (MITM cannot forge without the private key, per the strings [Update] Ed25519 signature INVALID - rejecting). But the leak is a fingerprinting primitive: exact build hash lets an attacker match reverse-engineering sessions across versions, and the signature blob is offline-analysable. Combined with P0.6 (bind-URL leak) this gives an attacker the whole update path map.
Fix
Require a short-TTL HMAC (signed with SERVER_TOKEN) on the manifest fetch, so only legitimately-registered clients see update info. Rate-limit the download endpoint independently of the manifest.

P1 · High

7 findings · fix within the release week
P1.1

HSTS downgrade window via Cloudflare rewrite

Proof
Origin: Strict-Transport-Security: max-age=63072000; includeSubDomains; preload. Public path project446.su: rewritten by CF to max-age=0.
Fix
Repair the CF page rule that strips STS. Or set the same 2-year value at the CF edge.
P1.2

Wildcard CORS on admin API without credentials

Proof
Access-Control-Allow-Origin: * on /api/admin/* OPTIONS. No Allow-Credentials, so cookies don't leak — but the full admin route inventory becomes enumerable to any web page.
Fix
Echo Origin back only if it's in an explicit allowlist (the panel's own origin). Do not wildcard.
P1.3

RBAC permission leak — 403 body exposes the entire model

Upgraded from H-tier
Proof
{"error":"Forbidden","missingPermission":"beta.view"}
Format is <resource>.<action>, and every admin route reveals its required permission when hit without it. The whole 36-permission RBAC model can be enumerated with one non-admin account.
Impact
Once the permission list is known, any mass-assignment vulnerability (see H8, H11) has a ready payload: permissions: ["admin.all","beta.write","users.delete", …].
Fix
Return generic 403 Forbidden to clients. Log the specific missing permission server-side for observability, not in the response body.
P1.4

Blanket cross-origin Allow-Headers: content-type

Impact
Combined with the panel's credentials: 'same-origin', this doesn't leak the session directly, but does let any cross-origin JS fire JSON POSTs and observe response codes — useful in a post-XSS-on-another-subdomain chain.
Fix
Allow only what's actually used, only from the panel origin.
P1.5

/api/seed is wired to the wrong permission

New this checkpoint
Proof
The seed / init endpoint (verified existence: OPTIONS /api/seed returns Allow: OPTIONS POST) requires news.edit instead of a dedicated permission scope.
Impact
Any user granted the low-privilege moderator role gets implicit admin-level seed capability. Depending on what seed does, that could wipe or overwrite data.
Fix
A dedicated system.seed permission, or — better — remove the seed endpoint from prod entirely. Seed belongs to a management script, not a public HTTP handler.
P1.6

CSP is Report-Only with unsafe-inline + unsafe-eval

Proof
Cloudflare emits: 
Content-Security-Policy-Report-Only:
  script-src 'unsafe-inline' 'unsafe-eval'; connect-src 'none'
The application itself emits nothing. Effective enforcement: none.
Impact
Any stored XSS becomes full impact — cookie theft, SPA takeover, phishing, exfil via any origin the browser will contact. custom_name and display_name fields (per the upstream csgo_gc source) accept arbitrary strings without sanitisation; if the P446 fork behaves the same, this is a stored-XSS vector waiting for the auth session to test.
Fix
Deploy an application-level CSP in Report-Only for one week, then enforcing: 
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'nonce-XXX';
  style-src 'self' 'unsafe-inline';
  img-src 'self' https://avatars.steamstatic.com data:;
  frame-ancestors 'none';
  base-uri 'none';
  form-action 'self';
P1.7

__Secure- cookie prefix fails on the :3000 bypass path

New this checkpoint
Proof
NextAuth issues __Secure-next-auth.callback-url and __Host-next-auth.csrf-token. RFC 6265 requires TLS for these prefixes. On https://project446.su/* they work; on http://213.152.43.203:3000/* they don't apply.
Impact
Authenticated actions can't be performed over the bypass path, but every public endpoint can — /api/pay/recent, /api/inventory/*, /api/pay/status, /api/me/prime, /api/auth/session. The whole public surface is readable without Cloudflare + without rate-limit + without HSTS.
Fix
Same as P0.3 — firewall :3000. This finding restates why P0.3 is not just an "in-depth" concern.

P2 · Medium

8 findings · fix before or shortly after launch
P2.1

X-Powered-By: Next.js

Fix
Set poweredByHeader: false in next.config.js.
P2.2

robots.txt allows everything, everywhere

Fix
Deny /api/ and /admin/ for all user-agents.
P2.3

SPF is ~all (soft-fail), no DKIM/DMARC

Impact
Mail runs on the same host as the app; phishing that spoofs @project446.su will likely pass at many recipients.
Fix
SPF -all, add DKIM signing, publish DMARC with p=quarantine then move to p=reject.
P2.4

Frontend SteamID regex is \d{15,20}

Fix
Exactly 17 digits, starts with 7656119. Enforce server-side too.
P2.5

/api/pay/status discloses provider configuration

New this checkpoint
Proof
GET /api/pay/status → 200
{"enabled":false,"primeThreshold":350,
 "methods":{"yoomoney":true,"anypay":false}}
Fix
Keep only enabled as a public UI hint. Move methods and primeThreshold to the authenticated donation page.
P2.6

Confirmed: direct-origin :3000 mirrors every public endpoint

Confirmation of P0.3
Proof
Every endpoint tested via https://project446.su/* returns identical body on http://213.152.43.203:3000/*, with all Cloudflare-provided headers absent (no CSP, no HSTS via CF, no CF-Ray).
Fix
Same as P0.3.
P2.7

/api/auth/callback/steam returns 42 KB of HTML on error

New this checkpoint
Impact
Hitting the callback without OpenID params returns the entire main-page HTML instead of a small error. Turns each invalid request into 42 KB of egress — a small DoS-amplification primitive.
Fix
Return { ok:false, error:"missing_openid_params" } JSON on invalid callback requests.
P2.8

Payment-webhook signature validation order is untestable while disabled

New this checkpoint
Impact
With payments off, every POST returns reason=disabled before signature verification runs — so from outside there's no way to confirm whether YooMoney's sha1_hash and AnyPay's signature are actually validated. The ordering matters: if the enabled-check sits before the signature-check, when payments turn on an attacker gets a distinguishing oracle (invalid_signature vs a full success:true).
Fix
Signature verification must be the first gate in the webhook handler. Only after a signature clears do you consult enabled / amount / duplicate. Also whitelist the YooMoney and AnyPay egress IPs at the CF edge.

Client-side patcher — status

Separate deliverable

The Windows client patcher (source/p446/p446_patcher.cpp, 34 patches, targets csgo_gc.dll v0.7.6.8) is a disk patcher on top of the P446 fork — not a port of the mikkokko/csgo_gc upstream. Everything the patcher touches (18 detectors, 3 auto-update entry points, HWID cave, SMBIOS/MachineGuid inline, GetPublicIP randomisation, distinct Steam handles per call-site, RestartLoop kill) is content the P446 fork added on top of mikkokko upstream — none of it exists in the upstream tree.

Verdict: release-ready. Post-patch verify pass confirms every byte. Version fingerprint check refuses to touch a non-v0.7.6.8 build rather than corrupting it. Recent upstream commits (through ccd769f 2026-07-23) are all CMake / graphics / crypto-lib swaps and do not affect what the patcher touches.

Three optional hardenings — not blockers, defence in depth: turn p446_memcheck from read-only observer into an active restorer; scan for indirect IAT calls to WinTrustVerify that the current inline patch might miss; audit whether any patched region indirectly enters the OpenSSL graffiti-signing path (upstream commit aae0b5f flags OpenSSL as unstable there). Full comparison: docs/p446_audit/PATCHER_vs_UPSTREAM.md.
